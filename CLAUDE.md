### Videos live in Notion: resolve + sync

Every video we work on is a page in the Notion content DB (`notion-pipeline.md` = live schema; flow `Idea → Scripting → Filming → Editing → Review → Ready → Posted → Archived`). Two standing rules:

1. **Resolve every video reference.** When Jason mentions a video by name or description, find its page before doing anything with it:
   ```bash
   ~/.local/bin/ntn datasources query 21bf6585-5e6b-81c2-b536-000b0adc0835 \
     --filter '{"property":"Title","title":{"contains":"<one distinctive keyword>"}}' \
     --json | jq -r '.results[] | [.id, .properties.Status.status.name, .properties.Title.title[0].plain_text] | @tsv'
   ```
   Title `contains` is case-insensitive; use one distinctive word, not the whole phrase. Multiple hits: list them and ask. Zero hits when we're starting real work on it: create the page (Status `Idea`, or the stage that matches) via MCP `notion-create-pages`.
2. **Status moves are automatic side effects.** When a pipeline step completes in a session, flip the page in the same turn (MCP `notion-update-page`, authored as Jason). Don't ask first:
   - `scriptwriter` lands a beat sheet → `Scripting` (the skill already sets this on create)
   - Jason says it's filmed / hands clips to `video-editor` / `recording-studio` wraps a film session → `To Edit` (+ set `Raw Footage` if he gives a link)
   - `auto-poster` succeeds (post now, schedule, or queue; not draft) → `Posted` + `Post Date` = the day it goes live (the scheduled date for a scheduled post). A schedule that later fails `--status` goes back to `Ready`.
   - Any other state Jason reports → the matching status
   The editing-stage flips (`Editing`, `Review`, `Ready`) happen in the `video-editor` project, not here.

Helper: `transcribe-url` — pulls a transcript from any video URL when needed (not part of the main pipeline).
Helper: `yt-download` — downloads any video URL as a Premiere-compatible MP4 (H.264 + AAC, always). Use it for every download that will be edited; bare `yt-dlp` hands back AV1/VP9, which Premiere rejects.
Helper: `idea-capture` — drop a video link in chat and it becomes a fully formatted `Idea` page in Notion (title = video title, cover = thumbnail, toggle-heading body: hook, chapter structure, why it works, twist for Jason, transcript). Feeds step 2.
Helper: `knowledge-compile` — refreshes the compiled `knowledge/` layer after high-signal research or positioning changes.
Helper: `carousel-generator` — standalone IG content lane: turns trends/news/posts into polished Instagram carousel PNGs + caption package (a HYBRID AI-cover + HTML-body engine). Lives here because it's image content, not video editing.
Helper: `voice-corpus-builder` — builds/refreshes `voice-corpus/` from Jason's own top videos (YT via yt-dlp, IG via the Apify MCP) and drafts `voice-dna.md` from it. The scriptwriter's few-shot source; re-run when a new batch of winners lands.
Helper: `dm-revival` — outreach lane outside the linear pipeline: grinds the IG DM inbox in real Chrome for lost leads and drafts personalized re-openers; resumable ledger in `outreach/dm-revival/log.json`.
Helper: `photo-finder` — finds the most aesthetic, classy lifestyle photos of Jason in the iPhone camera roll (osxphotos on the Photos library + a local SigLIP aesthetic/vibe rank; Claude only reads numbered contact sheets), then exports the picks as full-res originals to a Photos album and ~/Downloads. Needs Full Disk Access on the Claude Code binary (see the skill).

**One transcription engine.** Every skill that transcribes (transcribe-url, ig-competitor-research reels, auto-poster captions, voice-corpus-builder, yt-description chapter index) runs faster-whisper from the same persistent venv, `~/.cache/content-os/whisper-venv` (built once by `uv`, sentinel-gated, `CONTENT_OS_WHISPER_VENV` overrides). No whisper.cpp, no brew whisper-cli, no compilers. Each of those scripts calls `fw_fast.py` (an identical copy sits beside every one; edit transcribe-url's, copy it over the rest, the packager refuses a mismatch), which picks the fastest lane the machine has: NVIDIA GPU, then Apple Silicon GPU, then CPU, falling down a lane whenever one fails. AMD and Intel GPUs have no lane (the engine has no backend for them) and run on the CPU. `WHISPER_DEVICE=cpu|mps|cuda` forces one; `python fw_fast.py` prints this machine's lanes.

- Notion CLI (`ntn`) vs MCP head-to-head (2026-06-20): no real speed gap — both API-bound, sub-second. Splits by job. **Reads/queries → CLI**: MCP `notion-query-data-sources` is Enterprise-gated (400 upsell) so it can't query the DB on Jason's plan at all; `ntn datasources query` can, and `--json | jq` is ~50× leaner than raw (408 B vs 20.8 KB for 5 rows). **Writes → MCP**: `notion-create-pages` sets title+status+format+body in ONE call with a flat prop map + a 232-B response, authored as **Jason**. CLI write = 2 calls (`pages create` sets title-from-H1 + markdown body but defaults Status; then `ntn api PATCH` with verbose `{"status":{"name":...}}` JSON) and is authored as the **"Notion CLI" bot**. Gotcha: `ntn api` hangs on stdin in non-interactive Bash — always `</dev/null`, even with `-d` (a `-X PATCH -d` still hung 10 min on 2026-09-28; native subcommands are immune). More `ntn api` shape traps (hit 2026-07-02): paths need the `/v1` prefix (`/pages/...` → 400 invalid_request_url); method is a flag (`-X PATCH`), not positional. Page-body writes: `PATCH /v1/pages/{id}/markdown` — `insert_content` appends without touching existing blocks (`{"type":"insert_content","insert_content":{"content":md,"position":{"type":"end"}}}`), `update_content` takes `content_updates` (NOT `operations`) as its old_str/new_str array, and old_str must match Notion's *stored* markdown (it rewrites your input: linkifies `CLAUDE.md`, escapes `\[brackets\]`) — re-fetch the body first, never match against what you sent.

Wins, biggest first: faster-whisper's `BatchedInferencePipeline` (batch 16, beam 1) on ctranslate2's Apple GPU backend (`device="mps"`, ct2 4.9+, float16; ct2 silently runs int8 as float16 there): 146s of whisper became 10.6s; one yt-dlp call for metadata + the native m4a stream instead of a metadata call plus an mp3 re-encode; `local_files_only=True` skips the HF Hub round trip. - **video-editor's WhisperX on Macs: the 8-bit compression changes the words, the GPU does not (tested 2026-11-22; switched the same day on video-editor's `transcribe/full-precision-on-mac` branch: float32 on Apple Silicon when 14 GB is free, else int8; the GPU part was not done).** Its venv locks ctranslate2 4.8.2 (no Apple GPU backend) and Macs run large-v3 at `cpu int8`; NVIDIA machines already run `cuda float16`.
